    refactor(gc): the dead-session sweep asks only its own backend
    
    gc-sbx-state.bash looped _GLOVEBOX_VM_KNOWN_BACKENDS, sourced the seam
    once per member, and ran an sbx sign-in gate before the sbx listing. It
    now asks the one backend GLOVEBOX_VM_BACKEND selects, so ordinary Kata
    maintenance issues no sbx command and needs no Docker sign-in.
    
    The retention rule carries what the loop used to. A tagged state dir is
    reaped only by the backend named in its tag, and only when that backend's
    listing answered. An untagged dir keeps the older rule: a failed listing
    is what spares it.
    
    Reclaim.tla's site table said this pass draws its enumerate read from
    several backends. The machine and its properties are unchanged; the rows
    naming the site are corrected.
