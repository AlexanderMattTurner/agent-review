    fix(seed): drop a nested repo's missing files from the tar list
    
    _gb_seed_untracked_into lists a nested repository's tracked paths
    with `ls-files --cached`, which answers from that repository's
    index. A path deleted or renamed in the nested work tree is still
    named there. `tar --null -T` stats every member of the list, so one
    missing name fails the whole carry and the first Kata launch dies
    instead of seeding the nested tree as it stands.
    
    Skip a listed path that the work tree no longer holds. The test
    drives gb_seed_copy_untracked over a nested repository with a
    deleted file and with a renamed one.
