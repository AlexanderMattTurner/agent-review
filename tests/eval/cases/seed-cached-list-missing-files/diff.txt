    fix(seed): hold the ignored-file boundary at every seed the pack builds
    
    Three ways the seed carried files it promised to leave on the host.
    
    An untracked git repository inside the launch folder crossed whole. The
    outer `git ls-files --others` stops at its edge and names it as a bare
    directory, so the recursive tar archived its .git and every file its own
    .gitignore covered. Each one is listed through its own repository now.
    
    A history probe the untrusted-git wrapper refused read as "not a
    repository", which sends the pack down the no-history path: the whole
    folder, ignored files included. The probe tells git's own answers from the
    refusal now, and the two callers refuse rather than pack.
    
    A seed built on macOS carried the AppleDouble `._name` member bsdtar
    writes beside every file with extended attributes. The Lima transport
    suppresses those on the way over, but cannot reach into an archive that
    already stores them.
